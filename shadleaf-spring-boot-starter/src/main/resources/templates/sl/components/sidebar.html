The application's navigation, inside sl:sidebar-provider. One element serves both widths: from 768 px up it is a column beside the page, which the trigger collapses and expands; below that it is a panel over the page, which the trigger opens. It is a nav named "Main" (sl.sidebar.label; an aria-label replaces it) and a popover: the browser opens the panel in the top layer and closes it on Escape or a click outside. On a phone, Alpine moves the focus into the open panel and makes the rest of the page inert, and closes it when a link in it is followed. It holds sl:sidebar-header, sl:sidebar-content (groups of menus) and sl:sidebar-footer. With placement="header" it goes inside sl:site-header instead, where from 768 px it is a row of links; on a phone it is the same panel. The id the trigger points at (sl:sidebar-trigger's for). The edge it sits on: the start of a line (the left, or the right on a right-to-left page) or the end. Where it sits on a desktop: sidebar is a column beside the page; header a row of links inside sl:site-header (the header layout), which never collapses: collapsible, the collapsed state and the trigger do not apply there (the trigger is hidden), and side only picks the phone panel's edge. Collapsible items and the parts marked panel-only are left out of the row; the phone panel is the same for both. How it looks on a desktop: sidebar is a column along the edge with a border; floating a panel with a margin all round; inset lays the sidebar's ground around the page, which (sl:sidebar-inset) becomes a card on it. The phone panel looks the same for all three. In the header placement only inset counts: the page becomes a card below the header. How it collapses on a desktop: offcanvas moves it out of view entirely; icon narrows it to a strip of its menu buttons' icons (labels, badges, actions and sub-menus hidden; a menu button's tooltip shows its label); none never collapses it, and the trigger is hidden on a desktop. The phone panel is the same for all three.
