A form field: a sl:field-label, one control, and optionally a sl:field-description and a sl:field-error, in any order. Put th:field on the field, not on the control: the control takes it, gets the id the label points at (the field's name, email, also for a checkbox or switch), and an aria-describedby listing the description and, when the binding has errors, the error. The error shows the binding's messages. A field with errors gets data-invalid. Without th:field, set for to the control's id. Stack the label above the control, or put them side by side (a checkbox or switch, then its label). responsive stacks them in a narrow sl:field-group and puts them side by side in a wide one. The id of the control: for a field without th:field, or to use another id than the field's name. The control gets it when it has no id of its own, and the description and error ids derive from it.
