Tabs

Built from parts

Section titled “Built from parts”

Tabs are <sl:tabs> with an <sl:tabs-list> of <sl:tabs-trigger>s and an <sl:tabs-content> per tab, as in shadcn/ui. A trigger and its panel share a tab, and active on <sl:tabs> names the one that shows:

shadcn/ui calls these value and defaultValue; value is taken in Thymeleaf (th:value is Spring’s form value). The tabs need an id: the triggers and panels get ids derived from it and their tab (settings-account-trigger, settings-account-content), which link each tab to its panel (aria-controls, aria-labelledby). So a tab is letters, digits and dashes.

The server renders the active tab’s panel and hides the others (hidden), so the page is right before any script runs. The Alpine component slTabs then switches panels in the browser and adds the keyboard of the ARIA tabs pattern. An aria-label on the list names it, which helps when a page has more than one.

Tabs in the address

Section titled “Tabs in the address”

A trigger with an href is a link. Without JavaScript (or before Alpine starts) it loads the page with that tab active, so every panel is reachable; with Alpine the tab switches in place, and the page’s address becomes the link’s (history.replaceState), so a reload or a shared link opens the same tab. A click with Ctrl, Cmd or Shift still opens the link in a new tab or window. The controller reads the tab from the request:

Triggers without an href are buttons, which need Alpine: without it only the active panel can be seen. Use links for tabs that must work without JavaScript.

Keyboard

Section titled “Keyboard”

Tab moves into the list on the active tab, and out of it to the active panel (which takes the focus, as in Radix, so a panel without controls can be scrolled and read). In the list:

Key Does
Left and Right arrow The previous and next tab, wrapping around; they swap on a right-to-left page. Up and Down with orientation="vertical".
Home, End The first and last tab.
Enter, Space Shows the focused tab’s panel (for activation-mode="manual").

Disabled tabs are skipped. With activation-mode="automatic" (the default) a tab shows its panel as soon as the arrow keys reach it. manual only moves the focus, and Enter or Space shows the panel: for panels that take a request to show, such as ones loaded with htmx, so that arrowing past a tab does not load it.

Icons and disabled tabs

Section titled “Icons and disabled tabs”

A disabled button tab gets disabled; a disabled link tab loses its href and gets aria-disabled.

Find in page

Section titled “Find in page”

Once Alpine runs, the inactive panels are hidden="until-found" instead of hidden: the browser’s find-in-page, and a link to an element inside a panel (#billing-address), find their text, and the tab of the panel with the match becomes active (the beforematch event). This works in Chrome and Edge 102, Firefox 148 and Safari 26.2 (Safari and Firefox 139 to 147 do not scroll to the match yet). The server renders plain hidden: without Alpine a match would show the panel under a tab that stays inactive.

With htmx

Section titled “With htmx”

A panel that loads on first view. Each time a panel is shown, slTabs fires sl-tabs-show on it, so htmx can fetch its content the first time:

The server renders the active panel’s content itself: sl-tabs-show is only fired when a panel is shown in the browser, not for the one that is active when the page loads. The event does not bubble, so a panel’s hx-trigger never reacts to the tabs nested in it. activation-mode="manual" keeps the arrow keys from loading every panel on the way.

A swap that replaces the tabs shows the tab the new markup has active: send the active the user had (for example with hx-vals or hx-include) if it should stay.

History. htmx saves the page’s markup as it is when it navigates away, with the tab the user chose and any panel content loaded since; back restores exactly that. With link triggers the address has the tab too.

Left out

Section titled “Left out”
  • value/onValueChange and controlled state: the server renders the active tab; the sl-tabs-show event reports a switch.
  • dir: the arrow keys follow the page’s direction (dir on an ancestor or the page).
  • loop: the arrow keys always wrap around, as Radix’s do by default.
  • forceMount: every panel is always in the page; the inactive ones are hidden.

Attributes

Section titled “Attributes”

sl:tabs

Section titled “sl:tabs”
AttributeValuesDefaultDescription
idstringrequiredThe id of the tabs. The ids of the triggers and panels derive from it (settings-account-trigger, settings-account-content).
activestringrequiredThe tab of the trigger and panel that are active when the page renders, e.g. from a request parameter: th:active="${tab}".
orientationhorizontal verticalhorizontalvertical puts the tabs in a column next to the panels, and the up and down arrow keys move between them.
activation-modeautomatic manualautomaticautomatic: a tab shows its panel as soon as the arrow keys reach it. manual: the arrow keys only move the focus, and Enter or Space shows the panel; for panels that are slow to show, such as ones loaded with htmx.

Every prop can also be set from an expression: th:id="${...}". Any other attribute passes through to the rendered element, and class is appended.

Section titled “sl:tabs-list”
AttributeValuesDefaultDescription
variantdefault linedefaultdefault: the tabs sit on a muted track and the active one is raised. line: no track, a line under the active tab.

JavaScript

Section titled “JavaScript”

A small Alpine component, slTabs, is on <sl:tabs>: it renders as <div class="tabs" x-data="slTabs">.

  • Without Alpine the active panel shows, and link triggers load the page with another tab active. Button triggers need Alpine. Alpine is included by default; see Alpine.
  • It needs no Alpine plugin. If you load Alpine yourself (shadleaf.assets.alpine=external), plain Alpine is enough.
  • Keep your own x-data off <sl:tabs>. An element has one x-data; put yours on an element inside.
Event On Effect
sl-tabs-show a panel (it does not bubble) Fired when the panel is shown in the browser: a click, the keyboard, or find-in-page.
