Alert Dialog

Built from parts

Section titled “Built from parts”

An alert dialog asks a question the user has to answer before going on, such as “Delete this account?”. It is <sl:alert-dialog> plus its parts, as in shadcn/ui: <sl:alert-dialog-header> (holding an optional <sl:alert-dialog-media>, <sl:alert-dialog-title> and <sl:alert-dialog-description>) and <sl:alert-dialog-footer> with <sl:alert-dialog-cancel> and the action, a plain <sl:button>.

It works like a dialog, with the differences an alert dialog needs:

  • It has role="alertdialog", so a screen reader announces it as an alert and reads the description with the title.
  • A click outside does not close it: the user has to choose. Escape still does, as in Radix, and counts as cancel.
  • It has no close button in the corner.
  • <sl:alert-dialog-cancel> takes the focus when it opens, so pressing Enter straight away never confirms by accident. It closes the dialog (commandfor and command="close" are set for you) and says “Cancel” unless you give it text of its own (the default comes from the message sl.alert-dialog.cancel). It takes the button’s variant (default outline) and size, and passes any other attribute on to the button.

The action has no part of its own: what it does depends on the page. A type="submit" button in a form, a button with hx-delete, or one with commandfor and command="close" when closing is all it has to do.

Small, and with media

Section titled “Small, and with media”

size="sm" makes it narrower, centres the header and puts the two buttons side by side in equal columns. <sl:alert-dialog-media> shows an icon above the title.

In a default-size dialog on a wide screen, the media sits beside the title and description.

Destructive

Section titled “Destructive”

For an action that deletes something, give the action variant="destructive", and the media too.

Confirming with htmx

Section titled “Confirming with htmx”

The alert dialog can come from the server, as the dialog does: a Delete button in a row fetches it into an empty element on the page, and open shows it as soon as it is there.

The fragment has the question, and the destructive button sends the request:

The controller deletes, closes the dialog with the sl-dialog-close event (the same one that closes a dialog), says what happened in a toast and answers with nothing for the row, which removes it:

Closing returns focus to the Delete button that opened the dialog, but the swap then removes that button with its row, and focus would fall back to the top of the page. The toast cannot take it instead: it goes away after a few seconds, and the focus would fall with it. So the response moves the focus to what comes next: the next row’s button, re-rendered out of band with autofocus, which htmx focuses after the swap. After the last row that is the row before it, and once the table is empty, the button that adds a member. The toast is announced, so a screen reader user hears what happened and is where they can go on.

“Next” is the next row as the page shows it: htmx sends the page’s address in the HX-Current-URL header, so the controller can read the sort order from it, as sample-01’s /dialog page does.

Without JavaScript the same buttons need a page of their own for the question, or a form per row with <sl:alert-dialog> in the page and a type="submit" action.

Section titled “Attributes”

sl:alert-dialog

Section titled “sl:alert-dialog”
AttributeValuesDefaultDescription
idstringrequiredThe dialog's id, which the button that opens it points at with commandfor. The title and description ids derive from it.
sizedefault smdefaultSize of the dialog. sm is narrower, with the header centred and the footer's two buttons side by side.

JavaScript

Section titled “JavaScript”

An alert dialog uses the dialog’s Alpine component, slDialog; see Dialog.

  • Most of it works without Alpine. Opening from a button, closing with Escape or Cancel, and focus on Cancel are the browser’s. Alpine is needed for open and the sl-dialog-close event.
  • It needs no Alpine plugin.
  • Keep your own x-data off <sl:alert-dialog>: it would replace slDialog. Put it on an element inside.
