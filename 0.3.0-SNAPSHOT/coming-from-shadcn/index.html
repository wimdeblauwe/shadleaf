Coming from shadcn/ui

Most of what you know from shadcn/ui carries over. The component and part names map one to one (CardHeader is <sl:card-header>), and so do the variant and size names (variant="outline" size="sm"). The colour tokens are shadcn’s, verbatim: a theme from tweakcn or the shadcn theme generator drops in unchanged. Porting an example is mostly a matter of renaming tags.

The skins are shadcn’s styles too. shadleaf.skin=vega (the default) is shadcn’s classic look, and lyra its boxy and sharp one. shadcn’s other styles (Nova, Maia, Mira, Luma) are not available yet.

This page lists where Shadleaf differs. Some differences come from running on the server with Thymeleaf instead of in React; the others are deliberate, mostly for accessibility.

Because it is Thymeleaf, not React

Section titled “Because it is Thymeleaf, not React”

as instead of asChild

Section titled “as instead of asChild”

There is no asChild. A component that can render as a link takes as="a":

No utility classes in the library’s CSS

Section titled “No utility classes in the library’s CSS”

shadcn styles its components with Tailwind classes compiled into your application. Shadleaf ships its own stylesheet, which defines no utility classes, so it works in an application that does not compile Tailwind at all. Where a shadcn example relies on a utility class to change a component, Shadleaf has a prop instead:

shadcn/ui Shadleaf
<CardHeader className="border-b"> <sl:card-header border>
<Skeleton className="h-4 w-full" /> <sl:skeleton/> (a line is the default), shape="circle" for an avatar

Your own classes still work: class is appended to the component’s own, so class="w-64" sizes a skeleton when your application compiles Tailwind. See the adjustability ladder.

The avatar decides on the server

Section titled “The avatar decides on the server”

shadcn’s avatar waits in the browser for the image to load and shows the fallback until it has. Shadleaf renders the image and the fallback, and the stylesheet shows the fallback when the image has no src or an empty one, which is what th:src gives for a user without a photo. An image URL that fails to load is not detected yet.

Markup

Section titled “Markup”

The rendered markup uses class names (class="card-header") where shadcn uses data-slot="card-header", and a data-variant or data-size attribute only when the value is not the default. It matters only if you port CSS written against shadcn’s markup.

Deliberate differences

Section titled “Deliberate differences”

A button does not submit by default

Section titled “A button does not submit by default”

<sl:button> renders type="button"; shadcn’s Button leaves the type out, so it submits the form it is in. Write type="submit" on the button that should submit. See Button.

An alert is not announced by default

Section titled “An alert is not announced by default”

shadcn’s Alert always has role="alert", so a screen reader interrupts the user to read it. Most alerts are part of the page when it loads, where that interruption helps nobody. Add role="alert" yourself when an alert appears later, for example in an htmx response. See Alert.

Contrast

Section titled “Contrast”

A few of shadcn’s colour pairs are under the 4.5:1 contrast WCAG asks for small text:

  • destructive text on its light red tint (the destructive button and badge, the destructive alert);
  • muted text on a muted background (the kbd, the avatar’s initials).

Shadleaf mixes 20% of --foreground into the text colour in those places. It still follows your own --destructive and --muted-foreground, so your theme keeps working.

Where shadcn changes text to --muted-foreground on hover, Shadleaf keeps --foreground, for the same reason.

Only interactive elements react to hover

Section titled “Only interactive elements react to hover”

shadcn’s ghost badge changes colour on hover even when it is a plain label. A Shadleaf badge only reacts to hover, and takes keyboard focus, when it is a link (as="a").

Accessibility additions

Section titled “Accessibility additions”
  • <sl:card-title level="3"> is announced as a heading, so screen reader users can jump between cards. Without a level it is plain text, as in shadcn.
  • The avatar is hidden from assistive technology unless it has a label, as it usually sits next to the person’s name. With one, it is announced as a single image with that name.
  • The skeleton is hidden from assistive technology; put aria-busy="true" on the region that is loading.
  • Rendering fails when a component that needs an accessible name has none, such as an icon-only button without an aria-label.

Form controls

Section titled “Form controls”
  • <sl:input> only takes the text-like types (text, email, password, date, file, …). Checkboxes, radio buttons and switches are separate components, as in shadcn, but shadcn’s Input would accept type="checkbox".
  • <sl:native-select> takes <option> and <optgroup> as they are; there is no NativeSelectOption.
  • Checkbox, radio group and switch are the browser’s own inputs, styled, where shadcn builds them from buttons. They submit with the form without a hidden input of their own, th:field binds them, and the keyboard works as it does on any radio button or checkbox. There is no indeterminate checkbox yet.

Field

Section titled “Field”
  • th:field goes on <sl:field> (or <sl:field-set>), which wires up the label’s for, the control’s id, aria-describedby and aria-invalid, and the field’s data-invalid. In shadcn you set htmlFor, id, aria-invalid and data-invalid yourself.
  • <sl:field-error/> reads the binding’s messages; there is no errors prop. Content of your own replaces them, as children do in shadcn.
  • The error has no role="alert": after a full page load every error would be announced at once. The control is described by its error instead.
  • The field has no role="group", which gave every field an unnamed group. A set of options is a <sl:field-set>.
  • In an invalid field, only the label (or legend) and the error turn destructive; shadcn colours all the field’s text.
  • No FieldTitle, FieldSeparator or choice cards (a field inside a label) yet.

Additions

Section titled “Additions”
  • An input, textarea or native select with th:field marks itself aria-invalid when its field has errors, so the invalid style needs no markup of yours.
  • <sl:button loading> shows a spinner, disables the button and announces the busy state. shadcn has a separate Spinner for this.
