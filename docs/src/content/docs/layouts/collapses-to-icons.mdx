A sidebar for an application with more pages than fit in a header row: the application's name and logo at the top,
groups of pages (one with a [collapsible item](../../components/sidebar/#collapsible-groups) holding a sub-menu), a
footer with a link and the [user menu](../../components/user-menu/), and the page as a card beside it
(`variant="inset"`). The page's header is a [site header](../../components/site-header/) with the trigger, a
separator, the page's [breadcrumb](../../components/breadcrumb/) and the theme toggle.

On a desktop the trigger (or Ctrl/⌘+B) collapses the sidebar to a strip of icons (`collapsible="icon"`), with a
tooltip on every menu button, and a cookie remembers the choice. On a phone it opens the same sidebar as a panel.
Switch the preview to Phone to see it.

## The layout

The whole layout file. It has what [every layout needs](../../guides/application-shell/#what-every-layout-needs), and
it is the layout of the first sample application (sample-01's `layout/main.html`, which has four groups).
`hx-boost` on the body loads every page with htmx; see [With htmx](../../guides/application-shell/#with-htmx) for
the one check a controller then needs. Leave out the script and the attribute for a layout without htmx.

<LayoutCode id="layout--collapses-to-icons" part="template" />

Without `variant="inset"` the sidebar is a column along the edge of the screen; with `collapsible="offcanvas"` it
moves out of view instead of collapsing to icons. The [Sidebar](../../components/sidebar/) page has every part and
option.

## A page

A page passes its title, its breadcrumb's levels and its content. The levels are a `th:block` with `th:ref`, so
nothing of it is rendered where it stands; the layout puts them in its `<sl:breadcrumb-list>`.
