[Basecoat](https://basecoatui.com) brings shadcn/ui to any stack that writes HTML: CSS classes, a small script, and no
React. It is the most widely used library of its kind, at version 1.1 (November 2026). Shadleaf owes it a lot: its
skins follow Basecoat's style files.

## The same dialog

```html
<!-- Basecoat -->
<button type="button" class="btn" data-variant="outline"
        onclick="document.getElementById('edit-profile').showModal()">Edit profile</button>
<dialog id="edit-profile" class="dialog" aria-labelledby="edit-profile-title"
        onclick="if (event.target === this) this.close()">
  <div class="sm:max-w-sm">
    <header>
      <h2 id="edit-profile-title">Edit profile</h2>
    </header>
    <section>...</section>
    <footer>
      <button type="button" class="btn" onclick="this.closest('dialog').close()">Save</button>
    </footer>
  </div>
</dialog>
```

```html
<!-- Shadleaf -->
<sl:button variant="outline" commandfor="edit-profile" command="show-modal">Edit profile</sl:button>
<sl:dialog id="edit-profile">
  <sl:dialog-header>
    <sl:dialog-title>Edit profile</sl:dialog-title>
  </sl:dialog-header>
  ...
  <sl:dialog-footer>
    <sl:button type="submit">Save</sl:button>
  </sl:dialog-footer>
</sl:dialog>
```

In Basecoat you write the ids, the ARIA wiring and the close behaviour yourself, in every template. Its Jinja and
Nunjucks macros generate that markup for nine interactive components; there are none for Thymeleaf.

## Where Basecoat is stronger

- **Any stack.** Django, Flask, Express, Go, Rails, PHP or static HTML: the same classes everywhere.
- **No build at all.** A stylesheet from a CDN holds everything it needs; as a Tailwind plugin it mixes with your own
  utility classes.
- **Plain HTML** that you read, copy and change as you like, with no component engine between you and the markup.
- **A larger community**, with thousands of GitHub stars.

## Where Shadleaf is stronger

- **Components instead of markup.** One template per component, declared props that fail on a typo, and a fix that
  reaches every page. See [what a component engine adds](../#what-a-component-engine-adds).
- **Spring wiring.** `th:field` binding and validation errors, sorting and paging of a Spring Data `Page`, Spring
  Security's user, translated texts. In Basecoat all of that is yours to write.
- **More components.** Basecoat has no calendar, date picker or file upload, and its table is styling only; its chart
  and drawer are marked beta.
- **A strict Content-Security-Policy.** Basecoat's documented dialog markup, its dialog macro and the action buttons of
  its toasts use inline `onclick` handlers, which a policy without `'unsafe-inline'` blocks. Shadleaf renders none
  ([CSP](../../guides/csp/)).
- **Tested accessibility.** axe runs on every Shadleaf example in every skin, with keyboard and forced-colours tests;
  Basecoat publishes no such tests.

Both have the same eight shadcn/ui styles (vega, nova, maia, lyra, mira, luma, sera, rhea) and shadcn/ui's colour
tokens, so a theme works in both. Shadleaf adds one skin of its own, `sketch`, for mockups.

## Which one to choose

**Choose Basecoat** for shadcn/ui's look in a stack that is not Spring Boot with Thymeleaf, or in a Thymeleaf
application where you want to own every line of markup. **Choose Shadleaf** to write components instead of markup,
with forms, tables and security wired to Spring.
