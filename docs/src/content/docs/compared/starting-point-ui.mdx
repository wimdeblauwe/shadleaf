[starting-point-ui](https://startingpointui.com) describes itself as "the shadcn/ui design system for any web stack":
component classes for Tailwind CSS v4, with a small script for the interactive ones. It is young and moves fast, at
version 0.41 (November 2026). Its CSS was a reference for Shadleaf's components.

## The same dialog

```html
<!-- starting-point-ui -->
<button id="edit-profile-trigger" class="btn btn-outline">Edit profile</button>
<dialog class="dialog" data-sp-toggle="#edit-profile-trigger">
  <form class="dialog-panel">
    <div class="dialog-header">
      <h2 class="dialog-title">Edit profile</h2>
    </div>
    ...
    <div class="dialog-footer">
      <button type="button" class="btn btn-outline" data-sp-dismiss>Cancel</button>
      <button type="submit" class="btn">Save</button>
    </div>
  </form>
</dialog>
```

```html
<!-- Shadleaf -->
<sl:button variant="outline" commandfor="edit-profile" command="show-modal">Edit profile</sl:button>
<sl:dialog id="edit-profile">
  <sl:dialog-header>
    <sl:dialog-title>Edit profile</sl:dialog-title>
  </sl:dialog-header>
  ...
  <sl:dialog-footer>
    <sl:button variant="outline" commandfor="edit-profile" command="close">Cancel</sl:button>
    <sl:button type="submit">Save</sl:button>
  </sl:dialog-footer>
</sl:dialog>
```

The markup is close to Shadleaf's rendered output: both follow shadcn/ui's part names, on native elements.

## Where starting-point-ui is stronger

- **Any stack.** The same classes in Laravel, Rails, Django or a React application.
- **Wide range.** Around 50 components, among them some Shadleaf has not: a carousel, a command palette, a context
  menu, an OTP input, and chat message components.
- **Any shadcn/ui theme**, pasted in as it is, and right-to-left support.
- **Small script.** Vanilla TypeScript on native elements, with Playwright tests for each interactive component. Only
  its experimental inline event attributes need `'unsafe-eval'`.

## Where Shadleaf is stronger

- **No Tailwind build.** starting-point-ui is imported into your own Tailwind v4 build; there is no stylesheet to load
  without one. Shadleaf's jar ships its CSS.
- **Components instead of markup**, with declared props and one place to change. See
  [what a component engine adds](../#what-a-component-engine-adds).
- **Spring wiring.** starting-point-ui styles errors from `aria-invalid`; Shadleaf sets that, the error message and the
  label from `th:field`, and sorts and pages a Spring Data `Page`.
- **Nine skins.** starting-point-ui has shadcn/ui's default look; Shadleaf has all eight shadcn/ui styles and `sketch`.
- **Stability.** starting-point-ui is before 1.0 and its classes can change between versions.

## Which one to choose

**Choose starting-point-ui** for shadcn/ui's look in a non-Java stack, or in a Thymeleaf application that already
compiles Tailwind and where you want to own the markup. **Choose Shadleaf** to write components, with forms and tables
wired to Spring, and without a Tailwind build.
