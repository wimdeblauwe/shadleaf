A box with an icon, a title and a description that draws attention to a message in the page. It stays where it is until
the page changes.

<ComponentPreview id="alert--default" />

## When to use

- An error the server reports, such as data that could not be loaded.
- A notice, such as a trial that ends soon or a feature in beta.
- A warning above a form, such as a change that affects every user.

Use something else for:

- A short message about what just happened, that goes away by itself: a [toast](../toast/).
- Errors that belong to a whole form: [form errors](../form-errors/).
- A question the user must answer: an [alert dialog](../alert-dialog/).

## Built from parts

`<sl:alert>` holds an optional [`<sl:icon>`](../icon/), then `<sl:alert-title>` and `<sl:alert-description>`. The icon
takes the alert's colour and sits beside both. Use either part on its own.

## Announcing an alert

An alert is not announced by itself. Most alerts are part of the page when it loads, and a screen reader reads them in
order with everything else; announcing them too would interrupt the user for no reason.

When an alert appears later, for example in the response to an htmx request, add `role="alert"`. A screen reader then
reads it as soon as it is inserted. Like any other attribute, `role` passes through to the rendered element. An
alert that takes the focus when it appears (`tabindex="-1"` and `autofocus`, which htmx honours in swapped content) is
read out because of the focus, and needs no role; see [Forms with htmx](../../guides/forms-htmx/).

<ComponentPreview id="alert--announced" />

For a message that is not urgent, `role="status"` is announced when the user is idle instead of at once.
