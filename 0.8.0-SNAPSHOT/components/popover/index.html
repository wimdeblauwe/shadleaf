Popover

Built from parts

Section titled “Built from parts”

A popover is <sl:popover> with a <sl:popover-trigger> and a <sl:popover-content>, as in shadcn/ui. The content can hold a <sl:popover-header> with <sl:popover-title> and <sl:popover-description>, and anything else: text, a small form, links. <sl:popover> renders no element of its own: it gives the parts their ids.

The panel is a popover: it is drawn above everything else, Escape or a click outside closes it, and closing returns focus to the trigger. When it opens, focus moves to its first control (or to an element with autofocus), or to the panel when it has none; moving the focus out of it, with Tab past its last control for example, closes it. The trigger is a <sl:button> with popovertarget set to the popover’s id; any other button can open it the same way.

The panel is a non-modal dialog (role="dialog"): the rest of the page stays usable. The title names it and the description describes it (aria-labelledby and aria-describedby, with ids derived from the popover’s id: dimensions-title). A popover without a title needs an aria-label on <sl:popover-content>. level on the title makes it a heading.

Position

Section titled “Position”

The panel opens below its trigger, centred on it. side="top|right|bottom|left" and align="start|center|end" on <sl:popover-content> change that, and it flips to the other side when there is no room. right and left are the end and the start of a line, so they swap on a right-to-left page.

It is placed with CSS anchor positioning, which every current browser supports (Chrome and Edge 133, Safari 26, Firefox 147). In older ones the popover’s small Alpine component places it from the trigger’s position instead.

A form in a popover, with htmx

Section titled “A form in a popover, with htmx”

A form in the panel can post with htmx and swap only what it changes. An HX-Trigger: sl-popover-close response header closes the popover after a valid save, and focus returns to the trigger:

htmx fires sl-popover-close on the form; it bubbles up to the popover, which closes. A popover nested in another closes only itself. Back never brings a popover back open: whether it is open is not part of the markup htmx saves in its history cache.

Left out

Section titled “Left out”
  • PopoverAnchor: the popover is placed against its trigger.
  • PopoverPortal: the top layer does what the portal is for.
  • State in the browser (open/onOpenChange): the trigger opens it; the sl-popover-close event closes it.
  • modal: a popover never makes the rest of the page inert. Use a dialog for that.

JavaScript

Section titled “JavaScript”

A small Alpine component, slPopover, adds what the browser’s popover lacks: <sl:popover-content> renders as <div class="popover-content" role="dialog" popover x-data="slPopover">.

  • The basics work without Alpine. The trigger opens and closes the popover, and Escape and a click outside close it. Alpine is needed for moving the focus into it when it opens, closing it when the focus leaves, the sl-popover-close event, aria-expanded on the trigger, and placing it in browsers without CSS anchor positioning. Alpine is included by default; see Alpine.
  • It needs no Alpine plugin. If you load Alpine yourself (shadleaf.assets.alpine=external), plain Alpine is enough.
  • Keep your own x-data off <sl:popover-content>. An element has one x-data, and attributes on it end up on the panel, so yours would replace slPopover. Put it on an element inside the panel.
Event On Effect
sl-popover-close the popover, or anything inside it (it bubbles) Closes the popover.
toggle the popover (the browser’s own) Fired when it opens or closes, however that happened.
