htmx

htmx is an essential part of a Thymeleaf developer’s toolkit nowadays. It makes it easy to create rich, interactive UIs, without the need to write JavaScript yourself.

Shadleaf has no hard dependency on htmx, so it is not included by default. But both do work nicely together once your application loads htmx.

The components pass hx-* attributes through like any other attribute. They are built for it: dialogs, menus, popovers and toasts keep working when htmx swaps them in or out, and response headers such as HX-Trigger can close a dialog or show a toast.

Using htmx 4 is recommended, but Shadleaf also works with htmx 2: see Still using htmx 2?.

Some important points:

  • Shadleaf’s components use Alpine, so be sure to also load the hx-alpine-compat extension, which is included in the htmx webjar. Without it, an htmx swap resets attributes the components set, such as aria-expanded on a menu’s trigger.
  • The htmx scripts must load before the sl/layout :: assets because that contains the AlpineJS script.
  • webjars-locator-lite lets the script URLs leave out the version: Spring Boot adds it (/webjars/htmx.org/4.0.2/...). Without it, write the version in the URL yourself.
  • If you need a strict CSP, disable the indicator CSS via includeIndicatorCSS. Setting this to false avoids the inline <style> that htmx adds by default.
  • When the application is secured (with Spring Security for example), permit /webjars/** so htmx can be loaded on the login page as well.

Still using htmx 2?

Take note:

  • The config has other names. htmx 2’s includeIndicatorStyles is htmx 4’s includeIndicatorCSS (each ignores the other’s name), and allowEval: false turns off hx-on handlers and js: values, which htmx 4 has no setting for.
  • No Alpine extension. hx-alpine-compat is htmx 4’s; leave it out, and htmx can come after the assets fragment.
  • Use htmx-spring-boot 5.x. Version 6.x is for htmx 4.x.

The snippets in the docs are htmx 4. Some of those snippets need to be tweaked if you use htmx 2.

Below are the differences that matter for Shadleaf. Important differences of htmx itself can be seen at What’s new in htmx 4.

Inheritance

Section titled “Inheritance”

htmx 2 inherits hx-boost, hx-target, hx-select and hx-swap from any ancestor, without :inherited. So you write hx-boost="true" instead of hx-boost:inherited="true". To drop an inherited hx-select on one element, htmx 2 has hx-select="unset".

Request headers

Section titled “Request headers”
htmx 2 htmx 4
The element that sent the request HX-Trigger (its id), HX-Trigger-Name HX-Source, as tag#id (a#sort-name)
The target HX-Target (its id; none without an id) HX-Target, as tag#id, always (div#people-results, body)
Full page or part HX-Request-Type: full or partial

With htmx-spring-boot 5, getTriggerId() and getTriggerName() take the place of getSource() (@HxRequest(triggerId = ..., triggerName = ...)), and getTarget() returns people-results, not div#people-results. A link boosted from a <body> without an id sends no HX-Target, so getTarget() == null tells it apart; the fragment check works with both.

History

Section titled “History”

htmx 2 keeps a snapshot of the page in localStorage for each address it pushes (hx-push-url, hx-boost), and puts it back on the back button. A failed form keeps the user’s input in its value attributes there: for a form with personal data, set "historyCacheSize": 0 in the htmx config, or hx-history="false" on the page, which makes htmx ask the server again (HX-History-Restore-Request). A search field shows the value of the first load in a snapshot, so Tables with htmx puts hx-history="false" on its search form there. Before htmx 2 saves a snapshot, Shadleaf closes open dialogs and removes the toasts, so back never shows one.

Response headers and events

Section titled “Response headers and events”

htmx 2 also has HX-Trigger-After-Swap and HX-Trigger-After-Settle (addTriggerAfterSwap() and addTriggerAfterSettle() in htmx-spring-boot 5), whose events are lost when the swap removed the element that sent the request: use HX-Trigger. htmx 2 dispatches the events of HX-Trigger before the swap, where htmx 4 does it after. HX-Redirect, HX-Location, HX-Refresh, HX-Push-Url, HX-Replace-Url, HX-Retarget, HX-Reswap and HX-Reselect are the same in both.

Swapping

Section titled “Swapping”
  • htmx 2 does not swap 4xx and 5xx answers unless a responseHandling entry says so (htmx 4 has no responseHandling).
  • A response with only out-of-band content empties the target in htmx 2, so swapEmpty:true is not needed there.
  • hx-delete includes the enclosing form in htmx 2.
  • htmx 2’s hx-disabled-elt is htmx 4’s hx-disable, and htmx 2’s hx-disable (leave this element alone) is htmx 4’s hx-ignore.
  • Validating as you type is htmx 4 only. <sl:form validate> swaps with outerMorph and <hx-partial>, which htmx 2 does not have.
