Dialog

Built from parts

Section titled “Built from parts”

A dialog is <sl:dialog> plus the parts you need, as in shadcn/ui: <sl:dialog-header> (holding <sl:dialog-title> and <sl:dialog-description>), your own content and <sl:dialog-footer>. shadcn’s Dialog, DialogContent, DialogOverlay and DialogPortal are all <sl:dialog>: it renders the browser’s own <dialog> element, which is the panel, and its ::backdrop is the overlay.

The browser does the hard parts. A dialog opened as a modal is drawn above everything else, the page behind it is inert (no clicks, no focus, hidden from screen readers), focus moves to the first control in it, Escape closes it, and closing returns focus to the button that opened it. A click outside closes it too. The page behind it does not scroll.

The title names the dialog and the description describes it (aria-labelledby and aria-describedby, with ids derived from the dialog’s id: edit-profile-title). A dialog without a title needs an aria-label.

Opening and closing

Section titled “Opening and closing”

Every dialog has an id, and the buttons that open and close it point at it with HTML’s invoker commands: commandfor names the dialog and command says what to do. No JavaScript of yours is involved.

The close button in the corner does the same; close-button="false" leaves it out. <sl:dialog-footer close-button> adds an outline “Close” button after the footer’s own actions.

A dialog per row of a table takes its id from an expression, and so do the buttons:

Invoker commands work in every current browser. For older ones (Safari before 26.2), and for a click outside where the browser lacks closedby, the dialog’s small Alpine component stands in, so both still work with Alpine on the page. To react when a dialog closes, listen for the close event of the <dialog> element.

A form in a dialog

Section titled “A form in a dialog”

Put the form around the dialog, as shadcn’s example does, so the submit button in the footer submits it. After a full page post, the page renders again and the dialog is closed. To show the form’s errors in the dialog again, render it with open, below.

Rendered by the server: htmx

Section titled “Rendered by the server: htmx”

With htmx the dialog can come from the server when it is needed: a button fetches it into an empty element on the page, and open shows it as a modal as soon as it is there.

The fragment the controller returns has the dialog, and inside it a form that swaps only itself. The submit button sits in the footer, outside the form, and points at it with form:

With errors, the controller returns the form alone: the dialog stays open and focus moves to the first field with an error (see form errors). When the save succeeds, it closes the dialog with an HX-Trigger response header, swaps nothing where the form is, and updates the member’s row out of band:

htmx fires sl-dialog-close on the form that made the request; the event bubbles up to the dialog, which closes, and focus returns to the button that fetched it. When the response then replaces that button, as the new row does here, give the button an id (th:id="|edit-member-${member.id}|"): htmx moves focus to the element with the same id after a swap. Without one, focus falls back to the top of the page. Use HX-Trigger, not HX-Trigger-After-Swap or -After-Settle: those fire after the swap, when the element that made the request may be gone.

open needs Alpine (on by default: see Alpine); the browser has no attribute that opens a dialog as a modal. A dialog removed from the page while it is open, by any swap, takes its backdrop and the page’s inertness with it. Before htmx saves a page in its history cache (hx-push-url, hx-boost), open dialogs close, so the back button never brings one back.

Attributes

Section titled “Attributes”

sl:dialog

Section titled “sl:dialog”
AttributeValuesDefaultDescription
idstringrequiredThe dialog's id, which the buttons that open and close it point at with commandfor. The title and description ids derive from it.
openboolean—Open the dialog as soon as it is on the page, for a dialog the server renders in answer to a request (an htmx swap, or a page shown after a redirect). Needs Alpine.
close-buttonbooleantrueA close button (an x) in the corner.

Every prop can also be set from an expression: th:id="${...}". Any other attribute passes through to the rendered element, and class is appended.

JavaScript

Section titled “JavaScript”

A small Alpine component, slDialog, adds what the browser’s <dialog> cannot do: <sl:dialog> renders as <dialog class="dialog" x-data="slDialog">.

  • Most of it works without Alpine. Opening and closing with commandfor, Escape, a click outside and focus returning to the button are the browser’s. Alpine is needed for open, for the sl-dialog-close event, and for invoker commands and a click outside in browsers that lack them. Alpine is included by default; see Alpine.
  • It needs no Alpine plugin. If you load Alpine yourself (shadleaf.assets.alpine=external), plain Alpine is enough.
  • Keep your own x-data off <sl:dialog>. An element has one x-data, and attributes on <sl:dialog> end up on the <dialog>, so yours would replace slDialog. Put it on an element inside the dialog.
Event On Effect
sl-dialog-close the dialog, or anything inside it (it bubbles) Closes the dialog.
close the <dialog> (the browser’s own) Fired when it closes, however that happened.
