Avatar

Image and fallback

Section titled “Image and fallback”

Write both parts, as in shadcn/ui: <sl:avatar-image> with the picture’s src or th:src, and <sl:avatar-fallback> with what to show without one, usually initials or an <sl:icon>. The avatar shows the fallback when the image has no src or an empty one. A th:src whose value is null renders an empty src, so a user without a photo needs no th:if:

Both parts are always rendered, and the stylesheet decides which one shows. The hidden one is also hidden from assistive technology. The image lies over the fallback at the same size, so nothing moves when one replaces the other.

A photo that fails to load

Section titled “A photo that fails to load”

A photo URL that fails to load shows the fallback too: a 404, a URL your Content-Security-Policy’s img-src blocks, a file that is no image, or no network. So does a photo that is still loading, as in shadcn/ui; the picture replaces the fallback once it is there.

Shadleaf’s script marks each avatar image with data-status="loaded" when its picture has loaded, or data-status="error", and the stylesheet only shows an image that is marked loaded. So a broken image never shows, not even for a moment before the script runs. The script also marks images htmx swaps in, and an image whose src changes later (htmx swapping the attribute, or a script of yours): the fallback shows while the new picture loads.

Without the script

Section titled “Without the script”
  • Without JavaScript, nothing marks the images, so they lie over the fallback as plain images: a picture that loads covers it. One that fails shows the fallback through it in Firefox, which draws nothing for a broken image with an empty alt; Chromium draws its broken-image icon over it.
  • With JavaScript but without Shadleaf’s script (your policy blocks it, say), every avatar shows its fallback.

The script is part of the one in the assets fragment, whatever shadleaf.assets.alpine is: it is not an Alpine component, and works without Alpine on the page. One listener on the document handles every avatar, so a long list of them costs nothing extra.

Naming the avatar

Section titled “Naming the avatar”

An avatar usually sits next to the person’s name, so it is decorative by default and hidden from assistive technology. When there is no name next to it, give it a label: it is then announced as an image with that name, whichever part shows. aria-labelledby, pointing at a name elsewhere on the page, works too.

Left out

Section titled “Left out”
  • A delay before the fallback shows (Radix’s delayMs): the fallback shows at once while a photo loads. A photo from the browser’s cache is there before the first paint, so it does not flash.
  • A loading status event (Radix’s onLoadingStatusChange): read data-status on the image instead.

Attributes

Section titled “Attributes”

sl:avatar

Section titled “sl:avatar”
AttributeValuesDefaultDescription
sizesm default lgdefaultSize of the avatar.
labelstring—The person's name, for an avatar with no name next to it. It is then announced as an image with that name; without it the avatar is hidden from assistive technology.

Every prop can also be set from an expression: th:size="${...}". Any other attribute passes through to the rendered element, and class is appended.
