Theme Toggle

Usage

Section titled “Usage”

Put the theme script in the <head> of your layout, as Getting started shows, and the toggle wherever it belongs, usually the page header:

The toggle is an icon button that opens a menu with Light, Dark and System. Light and Dark are stored in the browser (localStorage, key shadleaf-theme); System removes the key, and the page follows the operating system again. The theme script reads that key before the first paint, so every page after the choice starts in the right theme, with no flash of the other one.

The button shows a sun in the light theme and a moon in the dark one. A screen reader hears something like “Theme, menu button”; in the menu, “Light, checked, menu item radio, 1 of 3” (the wording differs between screen readers).

One button

Section titled “One button”

as="button" makes it one button that switches between light and dark. It is a toggle button for dark mode: a screen reader hears “Dark mode, toggle button, pressed” while the page is dark.

Pressing it stores light or dark, so once pressed the page no longer follows the operating system. Use the menu where that matters.

What the server renders

Section titled “What the server renders”

The server cannot know what the browser stored, so neither the menu’s check mark nor the button’s pressed state is in the markup: the toggle’s Alpine component sets them when it starts. Nothing shows wrong in the meantime. The icon comes from the dark class the theme script put on <html> before the first paint, and the menu is closed until someone opens it. A toggle that htmx swaps in, or brings back from its history cache, works the same way.

Several toggles, several tabs

Section titled “Several toggles, several tabs”

Every toggle on the page shows the same state, and a choice made in another tab of the same site changes this page too. While the choice is System, the page follows the operating system when it switches between light and dark (at sunset, say). Each toggle on a page needs its own id when it is a menu:

Labels

Section titled “Labels”

The labels are messages, which your messages.properties can reword or translate:

sl.theme-toggle.label names the menu’s button and sl.theme-toggle.dark-mode the single button; an aria-label on <sl:theme-toggle> replaces either for one toggle.

There is no tooltip. The sun and the moon are what people look for, and a tooltip would only repeat the button’s name to a screen reader, as its description.

Without JavaScript

Section titled “Without JavaScript”

Nothing can store a choice without JavaScript, and the theme script cannot run either, so the page stays light. The toggle is then not shown at all (@media (scripting: none)), rather than shown and doing nothing.

Left out

Section titled “Left out”
  • More themes than light and dark. The theme script and the skins know the dark class only.
  • A choice stored on the server (a user setting). Render class="dark" on <html> yourself and leave out the theme script and the toggle; the toggle stores in the browser only.
  • The keyboard shortcut shadcn’s own site has (D). Your application can add one that clicks the toggle.

JavaScript

Section titled “JavaScript”

A small Alpine component, slThemeToggle, does the work: <sl:theme-toggle> renders as <div class="theme-toggle" x-data="slThemeToggle">, around a dropdown menu (whose own slDropdownMenu handles the keyboard) or a button.

  • It needs Alpine, and no Alpine plugin: it writes the key itself, not with $persist, which would store "dark" as JSON, quotes included, where the theme script expects dark. Alpine is included by default; see Alpine.
  • Attributes go to the button, class and your own x-data included; the wrapper around it has no box.
  • It changes nothing when it starts. The page is already in the stored theme; a page that sets the dark class some other way keeps it until someone chooses.
Event On Effect
sl-theme-change the document Fired after the theme changed: by a toggle, in another tab, or by the operating system while the choice is System. The detail is {theme: 'light' | 'dark' | 'system', dark: true | false}. For a chart that has to redraw, say.
