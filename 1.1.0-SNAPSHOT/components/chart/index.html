Chart

Built from parts

Section titled “Built from parts”

Recharts draws a chart in the browser, in the skin’s look. The template says what to draw, the controller gives the rows:

  • th:data takes a list of rows: records, objects or maps, or a Spring Data Page. They go into the page as JSON, written by Jackson.
  • The series parts (sl:chart-bar, sl:chart-line, sl:chart-area) name the property they draw in key, and carry the series’ label and color. The chart draws bars for bars only, lines for lines only, areas for areas only, and a composed chart for a mix.
  • The other parts add a grid, the axes, a tooltip and a legend. Every part is optional; their order is the order Recharts draws them in.
  • label names the chart for a screen reader. The chart takes the focus, and the arrow keys move the tooltip from one category to the next.

Colours

Section titled “Colours”

A series without a color takes the chart tokens in turn: the first var(--chart-1), the second var(--chart-2), up to --chart-5, then again from the first. A theme that redefines them recolours every chart. color takes any CSS colour, and color-dark a different one for the dark theme:

The colour becomes the CSS property --color-<key> on the chart, which is why a key is checked to be a CSS identifier: letters, digits, _ and -, not starting with a digit or -. A key that is not fails the render.

Stacked bars and a legend

Section titled “Stacked bars and a legend”

The legend lists the series by label, in the order of the series parts, like the tooltip.

Line chart

Section titled “Line chart”

margin leaves room left and right of the plot, so the first and last tick labels fit. curve sets how a line runs between the points (monotone, natural, linear, step), dots puts a dot on each.

dashed draws a series dashed (on sl:chart-area only its line, the fill stays), for a forecast or a target next to actual figures. The legend and the tooltip show it dashed as well. A row without a number (null) leaves a gap, so an actual line stops at the last month with figures while the dashed one carries on. join (on sl:chart-line and sl:chart-area) names the series a dashed line continues (join="actual"): the line starts at that series’ last number, without a duplicate in your rows, and the tooltip does not list the forecast for that month.

Area chart

Section titled “Area chart”

On an area, dashed dashes the line and the fill stays; a lower fill-opacity on the forecast sets it apart.

Tooltip

Section titled “Tooltip”

The tooltip shows the hovered category and every series’ label and value. indicator is the mark before each label: dot (the default), line or dashed. hide-label leaves out the category, hide-indicator the marks, and cursor="false" the highlight of the hovered category.

Formats

Section titled “Formats”

Instead of formatting functions, the parts take a named format, written with Intl in the page’s language (<html lang>, from Spring’s locale):

Format Writes For
number 1,234.5 numbers; the tooltip’s values by default
integer 1,235
compact 1.2K a value axis
percent 25% for 0.25
currency €1,234.50, with currency="EUR"
day Apr 1 dates
month-short Apr
month April
month-year Apr 2024
date Apr 1, 2024
time 10:00 AM

format on an axis writes its ticks, label-format and value-format on the tooltip its label and values. A format is an enum: a typo fails the render. A value of another kind (a date format on a name) is shown as it is.

For a label no format writes, format it in Java and give the tooltip that property in label-key: it then shows that property of the hovered row as its label.

Dates and time zones

Section titled “Dates and time zones”

The dates are read by their Java type, as Jackson writes them, never by the browser’s date parser (which reads 2024-04-01 as midnight UTC, the evening before in America):

  • LocalDate (2024-04-01) and YearMonth (2024-04) are calendar dates: shown as they are, in every time zone.
  • LocalDateTime (2024-04-01T10:00:00) is a time on the clock: shown as written.
  • Instant, OffsetDateTime and ZonedDateTime (2024-04-01T08:00:00Z) are moments: shown in the chart’s time zone. That is the request’s (Spring’s LocaleContextHolder, which a LocaleResolver that knows the user’s zone sets; the server’s otherwise), or the one time-zone names.

Right to left

Section titled “Right to left”

On a dir="rtl" page the category axis runs from right to left and the value axis stands on the right; the arrow keys follow what you see.

With htmx

Section titled “With htmx”
  • A chart that htmx swaps in draws itself; one it swaps out is cleaned up.
  • Before htmx saves a page for Back, the charts are put back to their skeletons, so the saved page holds none of the inline styles Recharts sets (a strict Content-Security-Policy would report them when the page comes back). Back draws them again.

Left out

Section titled “Left out”

These Recharts features have no counterpart yet: pie, radar and radial charts (pie charts are planned), horizontal bars, gradients, custom tooltip and legend content, icons in the tooltip and legend, reference lines and brushes. For anything else, sl-chart is a custom element: an application can write its own.

JavaScript

Section titled “JavaScript”

The chart is the one component that is no Alpine component: Recharts is a React library, and Shadleaf runs it on Preact (preact/compat), which makes the chart’s script some 50 KB (gzip) smaller.

  • JavaScript is required. Without it, the chart’s skeleton stays where the chart would be.
  • It loads when it is needed. Every Shadleaf script (shadleaf.assets.alpine bundled, csp or external) holds a loader of about 1 KB. It loads the chart’s script (about 125 KB gzip) when the first chart comes near the viewport, so a page without charts never loads it. It needs no Alpine.
  • It works under a strict Content-Security-Policy, without 'unsafe-inline' or 'unsafe-eval': the rows are a JSON data block (<script type="application/json">), which never runs, and the colours are set through CSSOM rather than a <style> element.
  • The server renders <sl-chart class="chart"> holding the data block, one element per part (<sl-chart-bar key="desktop" label="Desktop">) and the skeleton. The script mounts the chart beside them and marks the chart data-ready once it has drawn.
